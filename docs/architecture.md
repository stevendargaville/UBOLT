# UBOLT architecture

The long-form design of `libubolt`. The public headers in `include/ubolt/` keep each
class's contract; the reasoning, the conventions several classes share and the corner
cases live here. `AGENTS.md` is the short index, `docs/dsa.md` the DSA derivations,
`docs/dev/kokkos.md` the device-side discipline, and `docs/dev/history.md` how things got
this way (this file describes only what the code does now).

## Overview: the data flow

`tests/transportk.kokkos.cxx` is the reference assembly of the library, in this order:

1. **`ProblemSpec`** reads a JSON problem file (rank 0 reads, every rank parses the same
   broadcast bytes): dimension, `BackendKind`, mesh (`PlexMeshSpec`), SN order, a
   `MaterialSpec`, the painted regions and a `BCSpec`. Everything about HOW to solve
   stays on the command line.
2. **Quadrature**: `SNQuadrature` / `SNQuadrature2D` / `SNQuadrature3D` from the SN
   order. The quadrature comes first because the ordinate count is the phase space's.
3. **Discretisation**: a backend (`StructuredFD1D/2D/3D`, `UnstructuredDG`,
   `UnstructuredCG`) builds its DM, decides the parallel decomposition, writes
   `local_cells` (and `n_basis`) into the `PhaseSpace`, fixes the COO pattern and the
   boundary rows, and paints the material index per material entry (`mat_id_d`).
   The driver's `BuildBackend` is the one place that names concrete classes.
4. **Cross sections**: `GroupXSections::create(n_groups, disc.n_material_entries())` +
   `set_from_materials(mats, mat_id_d)`: per group, per material entry, on device.
5. **Terms**: a streaming term per backend, `RemovalTerm`, `ScatteringTerm` (CG:
   `SUPGTermCG`, `ScatteringTermCG`), plus a `GroupSource` (`GroupTransfer` /
   `GroupTransferCG`) for the rhs.
6. **`TransportOperator`**: the assembled terms in one MATAIJKOKKOS matrix, the
   matrix-free ones behind a MatShell that the KSP solves with.
7. **`TransportSolver`**: KSP + the composite preconditioner, optionally with a
   caller-owned `DSAPrecon` and, under `-precon_ref_shift`, one solver per
   `RefShiftPmats` bin.
8. **Group sweep** (in the driver): per group, re-point, refill, build the rhs, solve.
9. **Output**: `UboltWriteScalarFluxVTK` per group.

Everything after step 3 takes the `Discretisation` / `AngularQuadrature` bases, except the
streaming term (geometry and cosines) and `DSAPrecon::create` (geometry), which have one
overload or sibling per backend.

## Phase space and rows

`PhaseSpace` holds sizes only: `n_cells` (global), `n_angles`, `n_groups`, `n_basis`,
`local_cells`. Rows are angle-fastest: `row = (cell * n_basis + basis) * n_angles + angle`.
A (cell, basis) pair is a NODE and owns a contiguous run of `n_angles` rows, so the
angular integral, the scatter and the group transfer work per node and never learn what a
basis function is; the cross section of a row is per cell, `row / rows_per_cell()`.

- `n_groups` is metadata: groups are solved one at a time, so the row count, the
  sparsity and the matrix are the same for every group.
- The decomposition is in cells, decided by the backend's DM: all angles (and basis
  functions) of a cell are on one rank. `PhaseSpace::create` leaves `local_cells =
  PETSC_DECIDE`, and every `create` sized off it calls `check_decomposed()`.
- On `UnstructuredCG` the "cell" is a VERTEX (`n_cells` is the global vertex count), while
  materials and cross sections are per local ELEMENT, overlap included;
  `Discretisation::n_material_entries()` says which.

## Quadratures

`AngularQuadrature` is what every consumer that does not care how the set was built
reads:

- `n_angles()`, `sum_weights()` (the exact measure of the angular domain, 2 in 1D and
  4 pi in 2D/3D, passed in rather than summed), and `w_d()`, an `(n_angles, 1)` device
  view: the angular integral `UboltAngularIntegral` is a gemm against it.
- `dimension()`, `omega_host()` (3 per angle, zero past the dimension) and
  `reflect_host(axis)`, the ordinate with that axis's cosine negated. The reflection
  maps are built once by `set_directions`, which searches for each partner and checks it
  carries the same weight, so a set that is not reflection-symmetric fails at create.

The concrete sets add device cosine views (`mu_d`, `eta_d`, `xi_d`) and named reflection
accessors. `SNQuadrature` is an N-point Gauss-Legendre rule generated by Newton at
create (any even order). `SNQuadrature2D`/`3D` are the level-symmetric LQn sets, even
orders 2 to 18, from the generated `src/sn_lqn_table.hpp` (`python3
src/sn_lqn_table.py`); 2D tracks only `xi > 0` with doubled weights, 3D all eight octants
(twice the ordinates), and beyond S4 the weights are not equal within a set.
`tests/verify_quadraturek` checks the sets against their moment conditions.

**A new direction set** subclasses `AngularQuadrature` and calls `set_weights(w,
exact_sum)` and `set_directions(dim, mu, eta, xi, w)`. The scatter, the group transfer,
the output and both plex backends (which read `omega_host()` / `reflect_host()`) then
work unchanged. The structured streaming terms and the structured `DSAPrecon::create`
take the concrete SN classes (device cosines, the half-range current of the consistent
D), so a new set on a structured backend also needs those entry points widened.

**Pn seam.** `w_d` is the discrete-to-moment matrix with one isotropic moment. The
moment-to-discrete side is implicit: the `/ sum_weights` that `ScatteringTerm`,
`GroupTransfer` and `MaterialSourceTable::add_isotropic` apply. Anisotropic scattering
would add `n_moments()` and a moment-to-discrete view to the base, widen `w_d`'s column
dimension, and make the scatter cross sections per moment (`(g_from, g_to, l, cell)`,
LayoutRight so a slice stays contiguous). Keep `sum_weights` for the isotropic source.

## Discretisation backends

### The base and its contract

`Discretisation` owns the DM (and through it the mesh, the layout and the parallel
decomposition) and hands out what every dimension-independent piece of the library
needs: the COO slot maps (`CooPattern`), the boundary rows (`BoundaryInfo`), matrices
preallocated for that sparsity (`create_matrix`, deliberately NOT `DMCreateMatrix` - a
DMDA preallocates its whole stencil and PCAIR would see a different matrix), and
`comm()` / `phase_space()` / `n_material_entries()`. Geometry stays on the concrete
classes, because only the streaming term (and the DSA operator) reads it and those have a
sibling per backend anyway. The DM creates no solver matrices or vectors.

A backend's `create()`:

1. sets `comm_` and builds `dm_` - the DM decides the decomposition;
2. writes `ps.local_cells` (and `ps.n_basis` if not 1) and copies `ps` into `ps_`;
3. fills `oor_`/`ooc_` in slot order, `-1/-1` for a nulled slot (the slot stays in the
   values array, terms may write it, PETSc drops it - this keeps the value fills
   branch-free and the pattern the same for every group);
4. fills a host `BoundaryRows` (`reset()` gives the no-BC defaults) and calls
   `set_uniform_pattern(slots_per_row, rows)` (fixed slots per row, diagonal last) or
   `set_pattern(row_slot_offset, diag_slot, rows)` (CSR-shaped, any slot the diagonal);
5. overrides `destroy()` if it owns a PETSc handle beyond `dm_`, and
   `n_material_entries()` if materials are not per local cell (CG: per local element).

`set_pattern`'s device allocations are frozen in set and order: a moved allocation
shifts later buffers, changes the chunking a vectorised reduction picks and so the last
bits of a residual norm, and `tests/baselines/` is compared bit for bit.
`ghost_inflow_d` is allocated last and only under ghost-flux for that reason.
`UboltFillInflow` / `UboltZeroReflectRows` launch a kernel only if it can write
something (host flags `has_dirichlet_rows`, `has_reflect_rows`, `ghost_flux_vacuum`).

### Structured backends

`StructuredFD1D/2D/3D` are uniform-grid upwind finite differences on a DMDA.
`StructuredFD2D`/`3D` share `src/structured_fd_commonk.hpp`, templated on the dimension:
the DMDA patch and its global numbering (a 2D/3D DMDA numbers each rank's patch
lexicographically WITHIN the patch, so the local-to-global map is the authority), the
layout check `CheckDALayout<DIM>`, the row classification, the COO build and the box
painting. The only per-dimension inputs are the DMDA and each axis's (lo, hi) face ids -
PETSc's 3D box puts bottom/top on Z and front/back on Y, stated in one table per
backend. The ghost inflow is summed in ascending axis order from 0.0 and the centres are
`(idx + 0.5) * h`. `StructuredFD1D` keeps its own loops and its own `CheckDALayout`. A
BCSpec id outside a structured box's `1 .. 2 dim` faces is an error, as an unseen "Face
Sets" value is on the plex backends. Materials: `paint_intervals` (1D), `paint_boxes`
(2D/3D).

### Plex backends

`PlexDiscretisation` holds what `UnstructuredDG` and `UnstructuredCG` share: the mesh
(`create_plex_mesh` - a box built in code, quads/hexes or `simplex` triangles/tets, or a
file PETSc reads; distributed with a one-cell overlap under the backend's adjacency,
"simple" partitioner, no `DMSetFromOptions`) and the painting over the backend's
material unit (`paint_boxes`, `paint_cell_sets` for "Cell Sets" labels, and
`paint_boxes_over` to layer the two, by centroid). The rank-local helpers - the layout
check per stratum `CheckPlexStratumLayout`, outward area normal, BC validation, window
coordinates, the collective-failure idiom - are in `src/plex_commonk.hpp`. Both backends
take the quadrature as the `AngularQuadrature` base and read its host directions.

Construction is two-stage because the mesh decides the global count: `create_mesh`, then
`PhaseSpace::create` off `n_global_cells()` (`n_global_vertices()` on CG - never
`n_x * n_y`, a simplex box has 2 or 6 cells per box cell), then `create(ps, quad, bcs,
...)`. Local cell k is the k-th owned cell in DMPlex point order, asserted by
`CheckPlexStratumLayout`. BCs are keyed by "Face Sets" values, which on a box ARE the
`FACE_*` ids; a reflective face must be AXIS-ALIGNED (the mirror of an ordinate in a
general plane is not an ordinate): PETSC_ERR_SUP otherwise.

A configuration `create()` cannot build is usually found by one rank (a bad cell, a
non-axis-aligned reflective face, a window of the wrong shape, a mixed-cell-type CG
mesh); the first failure is recorded and every rank errors together at the next
`CollectiveFailure`, so no rank is left waiting in a collective.

**`UnstructuredDG`, order 0.** The cell-integrated balance divided by the cell volume,
upwind flux on every face: with `s_f = Omega . nA_f` (outward area-weighted normal), an
outflow face adds `s_f / V_c` to the diagonal and an inflow face adds it to the
neighbour's slot. On a uniform quad/hex box that is the structured stencil to rounding
(`verify_plexk` checks it matrix for matrix). Face adjacency, one-cell overlap.

**`UnstructuredDG`, order 1.** A MODAL basis per cell, `phi_0 = 1` and `phi_1..dim`
linear, orthonormal in `(1/V) int_c phi_i phi_j` via the Cholesky factor of the cell's
second moments from a fan of simplices (exact for planar faces). So the mass matrix is
the identity and removal, scatter and source stay per node; the source lands on basis 0
only, and the scalar flux written out is the cell average (the driver adds the slope as
`scalar_flux_grad_*` fields via `scalar_flux_gradient`). Ghost-flux only.

**`UnstructuredCG`.** Continuous P1 (triangles/tets) or Q1 (quads/hexes) at the
vertices with CONSISTENT SUPG: the whole residual is tested with `v + tau Omega . grad
v`, which is Wang's SAAF-tau written from the first-order side, `tau = min(1 / sigma_t,
h_Omega / zeta)` per (element, angle, group) (`UboltSUPGTau`), `zeta` a create argument
(`mesh.supg_zeta`, 0.5 by default). Rows are per unit lumped mass. FEM-closure overlap,
so a vertex's whole star is local; element tables M, G, K from PetscFE; nodal fields
travel through a dof-1 vertex twin DM (`nodal_global_to_local`). Weak boundary
conditions with a lumped face mass. SUPG is not adjoint-consistent, and tau depends on
`sigma_t`, so there is no group-independent streaming matrix on this backend.

## Slots and COO assembly

Every assembled term adds into ONE shared values array (`TransportOperator`), written
through the backend's slot maps, then one `MatSetValuesCOO(INSERT_VALUES)`
(`-ubolt_coo_two_call`: one call per term, bitwise the same). The sparsity is fixed once
by the backend; a group is a values-only refill. The slot order per row is a convention
the backend and its streaming term share:

| Backend | Slots per row, in order |
|---|---|
| `StructuredFD1D/2D/3D` | one upwind slot per axis in axis order (x, y, z), then the diagonal |
| `UnstructuredDG` order 0 | one per face in CONE order, then the diagonal (`n_faces + 1`) |
| `UnstructuredDG` order 1 | `n_basis` per face in cone order, then the own `n_basis`; the diagonal is own slot i |
| `UnstructuredCG` | the star's other vertices in point order, one mirror slot per reflective axis at the vertex, then the diagonal |

- The upwind neighbour per angle is fixed at preallocation from the sign of the cosine
  (structured) or of `s_f` (DG), so fills never branch on which neighbour is upwind;
  the `-1` nulls do the selection. A face slot is live only on an interior inflow face
  (or, under ghost-flux, a reflective one, pointing at the mirrored angle in the same
  cell - always rank-local).
- Nothing may assume the diagonal is the last slot: use `diag_slot_d`.
- CG fills are a row-parallel GATHER over the vertex's star (each star entry knows its
  slot inside the row, `star_slot_d`): no atomics, deterministic, which is what lets
  `add_diagonal` be bitwise the assembled diagonal.
- The COO indices are GLOBAL and come from the DM (the DMDA local-to-global map, the
  plex global section), never from assumed arithmetic. `docs/dev/kokkos.md` has the
  device-side rules.

## Boundary conditions

`BCSpec` maps a boundary label id ("Face Sets" value; the structured `FACE_*` ids match
PETSc's box convention) to a family, `VACUUM` (with a prescribed isotropic,
angle-integrated inflow, shared over the ordinates as `inflow / sum_weights`, and an
optional tangential window) or `REFLECT`. An unset id is cold vacuum. The label only
says which family a face is; what happens per row is decided by the sign of
`Omega . n`. The `VacuumTreatment` is a whole-spec discretisation choice.

### The BC contract

`BoundaryInfo::is_bc_row_d` flags the rows the assembly owns. A term contributes
NOTHING to a flagged row, in `assemble_add` and in `apply_add`: after the assembled terms
run, `TransportOperator` (`SetBoundaryRows`) writes those rows itself - the identity, plus
the -1.0 in `reflect_slot_d` on a reflective row - and a matrix-free term adding to them
would take that back off. The contract is about what a term WRITES: the scatter still
reads every angle when it integrates the scalar flux (a reflective row's flux is real
flux in the cell). An rhs builder owes the flagged rows the same: `UboltFillInflow` writes
the per-row inflow onto a Dirichlet row, `UboltZeroReflectRows` zeroes a reflective one,
and `GroupSource` / `MaterialSourceTable` skip flagged rows.

Under the default ghost-flux treatment there are NO flagged rows on any backend, and the
contract is vacuous; it binds under Dirichlet-cell (structured and DG0 only).

### Vacuum treatments

- **`GHOST_FLUX` (default).** An inflow boundary cell stays an ordinary unknown with its
  full diagonal. Each slot pointing out of the domain takes its own face's ghost value:
  on a vacuum face it is nulled and its coefficient times the face's per-angle inflow
  (windowed) is summed into `BoundaryInfo::ghost_inflow_d`, which `UboltFillInflow` ADDS
  to the rhs (so the source fills add too); on a reflective face it points at the
  mirrored angle in the same cell. A mixed corner takes each face's own value with no
  precedence rule. On CG the same idea is a weak boundary term with a lumped face mass.
- **`DIRICHLET_CELL` (opt-in, structured and DG0).** An inflow boundary row is REPLACED:
  the identity with the inflow on the rhs (vacuum), or `psi(a) - psi(partner) = 0`
  (reflective). The boundary sits at the cell centre rather than the face, an O(h)
  difference. DG1 and CG refuse it (PETSC_ERR_SUP).

### Dirichlet-cell corner rules

Structured backends (`src/structured_fd_commonk.hpp`, and the 1D loops): a row is a BC
row iff its upwind neighbour on some axis is outside the box. If ANY face it comes in
through is vacuum the row is Dirichlet - vacuum wins at mixed corners and edges - and
the value and window are the first vacuum inflow face's in axis order x, y, z. Else the
partner composes the per-axis reflection maps over every inflow axis (a triple flip at
a 3D corner between three reflective faces), still one column, in slot 0. The partner
must itself be interior: a reflective face on a single-cell-wide direction is
PETSC_ERR_SUP.

DG0 (`UnstructuredDG`): a row is a BC row iff some BOUNDARY face (support size 1) of its
cell has `s_f = Omega . nA_f < 0`. If any such face is vacuum the row is Dirichlet, the
winner being the incoming vacuum face with the lowest DOMINANT normal axis (x < y < z),
ties by face point number - on a box, the structured "first vacuum inflow face in axis
order". Else the row is identity minus the partner, the -1.0 in the slot of the first
incoming reflective face in cone order, the partner composing the reflection maps over
the axes of the incoming reflective faces. The partner's own row may be Dirichlet - a
reflective plane meeting a slanted vacuum face, the usual symmetry-reduced geometry,
where `psi(a) = psi(partner) = inflow` is a good pair of equations - but not reflective
(a single-cell-wide direction between two reflective faces): PETSC_ERR_SUP. Windows are
tested on the face CENTROID along the non-dominant axes, ascending, inclusive - the
boundary cell's centre on a quad/hex box.

Known limitation: on a non-box mesh where two incoming vacuum faces of a cell share a
dominant axis, the tie-break by rank-local point number can pick a different winner in
serial and parallel (Dirichlet-cell with windowed or unequal inflows only).

### The opposite-ordinate identity

Under ghost-flux, with P swapping (cell, Omega) and (cell, -Omega), the assembled
streaming + removal block satisfies `A^T = P A P` on the structured backends for ANY mix
of vacuum and reflective faces (inflow values and windows touch only the rhs; sigma_t
may vary cell to cell), because no row's stencil depends on which direction it is for.
It is what a half-quadrature preconditioner applied transposed on the other half rests
on. It does not hold under Dirichlet-cell, and the matrix-free isotropic scatter commutes
with P but is not symmetric once the quadrature weights differ (level-symmetric beyond
S4).

On the plex DG backend the rows are per unit volume, so with V the cell volumes expanded
to rows the VOLUME-WEIGHTED operator `S = V A` satisfies `S^T = P S P` - exactly off the
diagonal, to rounding on it (a cell's outward nA_f sum to zero only to rounding). A
itself satisfies only the similarity `A^T = V (P A P) V^{-1}`: on a mesh with unequal
volumes the transposed apply of a hierarchy built for one half is wrapped in the V
scalings, `y = V^{-1} M^{-T} (V x)` (V commutes with P). On a uniform box V is a multiple
of the identity. At DG1 the identity holds to rounding too, reflective faces included:
the face couplings pair up across the face, and the own-cell block is antisymmetric in
Omega up to the divergence theorem on the cell. CG-SUPG is not adjoint-consistent and
has no such identity. `verify_2dk`, `verify_3dk` and `verify_plexk` check it.

## Materials and problem files

`MaterialSpec` is `BCSpec`'s sibling for cell data: per material, per group `sigma_t`,
`sigma_s[g_from][g_to]` and an isotropic external source, DENSE ids 0..n-1 because the
tables reach device kernels. Which cells are which material is geometry, painted by the
backend into `mat_id_d` (plex backends remap "Cell Sets" values to ids at paint time).
The expansion goes through surfaces the terms already consume -
`GroupXSections::set_from_materials` and `MaterialSourceTable` (behind
`GroupSource::add_external`, `UboltFillSource`, `UboltFillCellSource`) - so the terms
never learn materials exist. `ProblemSpec` fills all of this from one JSON file; the
schema is `docs/problem_files.md`, the walkthrough `docs/problem_setup.md`.

## Terms and the operator

`OperatorTerm` is the seam for lhs physics: `assembled()` / `matrix_free()` (at most
one; `TransportOperator` partitions the terms at every `assemble()`, so a term like
`RemovalTerm::set_matrix_free` may switch before the first one), `set_group(xs, g)`,
`assemble_add(coo_values)`, `apply_add(x, y)`, and `has_diagonal()` /
`add_diagonal(d)`. The diagonal a term adds must be the same arithmetic, in the same
order, as what its `assemble_add` writes into the diagonal slot:
`TransportOperator::diagonal()` composes the diagonal from the terms (then 1.0 on BC
rows), and the removal stage uses it when a diagonal-carrying term is applied
matrix-free (`-matfree_removal`), so the assembled matrix is missing it.
`-check_matfree` checks it bitwise.

| Term | Kind | Notes |
|---|---|---|
| `StreamingTerm1D/2D/3D` (`StructuredStreamingTerm`) | assembled | One kernel templated on the axis count; takes the concrete backend and SN set |
| `StreamingTermDG0` / `StreamingTermDG1` | assembled | Read the ordinates off the backend (no quadrature argument); check the order |
| `RemovalTerm` | assembled or matrix-free | `sigma_t` on the diagonal slot; any backend except CG |
| `ScatteringTerm` | matrix-free | Per node: integrate, scale by `sigma_s(g, g)`, subtract `/ sum_weights`; persistent scratch |
| `SUPGTermCG` | assembled | Streaming + SUPG + removal + weak BCs in one term: tau depends on `sigma_t` |
| `ScatteringTermCG` | matrix-free | Through `UnstructuredCG::add_weighted_load`; owns Vecs, hence `destroy()` |

`TransportOperator::create(disc)` preallocates one matrix; `add_term` takes terms it does
not own (a const pointer is never re-pointed by `set_group`, fine for streaming);
`assemble()` zeroes the shared values, runs every assembled term, writes the BC rows and
calls `MatSetValuesCOO`; `mat()` is the MatShell (assembled matvec + every matrix-free
`apply_add`), `assembled_mat()` the matrix. `assemble_subset` builds a matrix of some
terms only (the streaming-only pmat).

## The group sweep and new physics

Groups are ordered high energy (0) to low. The driver's sweep, per group g:

1. `op.set_group(xs, g)` (host pointer swaps), then `op.assemble()` unless the assembled
   matrix is group-independent (`-matfree_removal`: streaming only, assembled once);
   `dsa.set_group(...)` if there is a DSA.
2. Rhs: `VecSet(b, 0)`, `UboltFillInflow`, `GroupSource::add_external(g, b)`,
   `UboltZeroReflectRows`, then `add_transfer(g_from, g, b)` for every solved
   `g_from < g`.
3. Pick the solver (one, or the group's ref-shift bin); `create` it the first time,
   otherwise `refresh()` (the removal stage re-reads its blocks).
4. `solve`, then `GroupSource::set_scalar_flux(g, psi_g)`: integrate once per solved
   group (CG keeps the nodal flux owned + overlap, one halo exchange per group).

With downscatter only the group system is block lower triangular and one forward sweep
is exact. `GroupXSections` tables are LayoutRight with the group slowest, so a group
slice is a contiguous per-cell view the single-group terms take unchanged.

What each extension would touch:

- **Upscatter**: `add_transfer` already works for any (g_from, g_to) and the cached
  fluxes survive across sweeps. Missing: an outer iteration in the driver and a
  convergence measure (e.g. the flux change computed while overwriting the cache).
- **Time dependence (implicit Euler)**: the lhs `1/(v dt)` is a diagonal term like
  `RemovalTerm` (with `set_group`, `has_diagonal`/`add_diagonal`), or folded into an
  effective `sigma_t`; the rhs `psi_old/(v dt)` is a `GroupSource`-style contribution,
  not an `OperatorTerm`.
- **Fission**: within-group `chi nu sigma_f` is scatter-shaped (a `ScatteringTerm` with
  an effective cross section); group-to-group fission is a `GroupSource` contribution
  plus an outer (power / k) iteration in the driver. The materials schema already
  accepts and ignores `Sigma_f`, `Nu`, `Chi`.
- **Anisotropic scattering**: see the Pn seam under Quadratures.
- **Transposed solves**: would want an `apply_transpose_add` on `OperatorTerm`; add it
  with the first user.
- On CG every new term needs a sibling written through `add_weighted_load` (the SUPG
  test function weights every term).

The sweep itself stays in the driver until a second sweep strategy justifies promoting
it into the library.

## The preconditioner

`TransportSolver::create(comm, op, pmat, dsa, block_scale)` builds a KSP on `op.mat()`
with a multiplicative `PCCOMPOSITE` (`-pc_composite_type additive` selects the additive
form; `KSPSetFromOptions` runs last):

| Index | Stage | What it is |
|---|---|---|
| 0 | `RemovalPCShell` | `ElementBlockInverse` of the OPERATOR's (cell, angle) blocks: point Jacobi at `n_basis` 1, block-Jacobi at DG1. Under `-matfree_removal` `setup(A, diag)` takes the composed diagonal |
| 1 | PCAIR (`-sub_1_pc_air_*`) | PFLARE's AIR on pmat, inverting the streaming. With `block_scale` a shell (`BlockScaledStreamingPCShell`) builds PCAIR on `D^{-1} pmat` and applies it to `D^{-1} r`; the inner PC keeps the `sub_1_` prefix |
| 2 | `DSAPCShell` (optional) | `DSAPrecon::apply`, `P D_diff^{-1} R`; its inner solve under `-dsa_` |

- **`ElementBlockInverse`** reads the n_basis x n_basis block of each (cell, angle)
  straight off a MATAIJKOKKOS matrix's device CSR (strided by `n_angles` under the row
  layout, so not PETSc's contiguous-block inverse) and inverts it on device; `apply` is
  `D^{-1} x`, `scale` is `D^{-1} A` on the same pattern (bumping the MPI matrix state so a
  PC sees the new values). Block scaling is a preconditioner-only change: operator, rhs
  and monitored residuals are untouched. It is what lets PCAIR coarsen DG1 at its default
  strong threshold. Default ON on DG and CG, OFF on the structured backends.
- **pmat choices** (driver): the assembled operator (default); a streaming-only copy
  (`-precon_stream`); the assembled matrix itself under `-matfree_removal` (streaming
  only, so PCAIR sets up once for the sweep); or a `RefShiftPmats` bin
  (`-precon_ref_shift`, needs `-matfree_removal`).
- **`RefShiftPmats`**: k copies of the streaming matrix, each carrying `alpha_k *
  D_ref`, D_ref a reference group's per-cell `Sigma_t`. Groups are sorted by support
  (the cells where `Sigma_t > 0`) into classes, one reference per class, binned per
  class (`-precon_ref_k` bins per class, default rule: mismatch within 3, at most 3
  bins); a void cell's pmat row is the bare streaming row the operator has there, and the
  streaming-only groups (`Sigma_t` zero everywhere) share one unshifted bin whose pmat IS
  the streaming matrix. The driver
  keeps one `TransportSolver` (one PCAIR hierarchy) per bin.
- **DSA**: with a DSA stage the composite updates its intermediate residuals with the
  AMAT (`PCSetUseAmat`), because pmat carries no scattering. The derivations, the
  per-backend diffusion operators (structured, DG0 and DG1 on the plex, CG), the
  consistent D and the void bridge/mask are in `docs/dsa.md`.
- `refresh()` re-takes the removal blocks after a group's refill; PCAIR tracks pmat's
  state itself.
- `-diag_scale` (driver only) scales the assembled operator and rhs by the inverse
  diagonal; the matrix-free scatter stays unscaled, so it is refused with
  `-matfree_removal` and `-precon_dsa`.

## Output

`UboltWriteScalarFluxVTK(ps, disc, quad, psi, n_extra, extra, filename)` integrates with
`UboltAngularIntegral` onto a dof-1 twin of the backend's DM and lets PETSc's VTK viewer
gather and write: `.vts`/`.vtr` on a DMDA, `.vtu` on a DMPlex (owned cells only; on CG
the flux is point data, `scalar_flux.nodal`). Extra fields are `UboltCellField`s, one
value per material entry; the driver writes `sigma_t`, `source` (via
`UboltFillCellSource`) and, at DG1, `scalar_flux_grad_*`. `ProblemSpec::check_flux_vtk`
validates the extension for the backend before the solve.
